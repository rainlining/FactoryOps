# Proposal：从工作台处理批次审批

- `status`: `design-reviewed`
- `learning_level`: `standard`

## 动机

连续检测已经能把高风险批次路由为 `WAITING_FOR_APPROVAL`，但用户无法查看审批依据或作出决定，流程停在不可操作的占位节点。本 Change 提供一个可信、可持久化、可回放的审批闭环。

## 范围

- 在工作台展示待审批批次、Risk 建议、批次结论与 Run 证据。
- 支持批准建议动作、驳回建议动作、要求复检和升级主管。
- 保存审批人、意见、决定、时间、版本和原始 Run，不覆盖旧事实。
- 要求复检创建新的派生队列项；高风险批准记录为“待业务系统执行”，不伪称物理产线已动作。
- 重复相同命令幂等；不同终态命令冲突拒绝。

## 非目标

- 不直接控制 PLC、MES 或真实生产线。
- 不新增 Kafka topic、权限平台或组织账号系统。
- 不让 LLM 决定审批状态迁移。

## 依赖

Stacked 在 `2026-08-22-scan-factoryops-batch-queue` 之上，消费其 `WAITING_FOR_APPROVAL` 队列项、批次 Run 和持久化历史。

## 学习等级

`standard`。复用项目已有审批、幂等和审计模式；新增重点是面向用户的审批闭环与工作台状态映射。
